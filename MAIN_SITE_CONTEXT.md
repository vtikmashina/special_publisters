# Контекст основного сайта спецпроектов Паблистеров

Этот файл описывает основной лендинг `https://special.publisters.ru/`.

## Назначение

Основной сайт - интерактивный промо-лендинг отдела спецпроектов Паблистеров. Его задача: показать подход команды, набор инструментов, примеры механик и быстро вывести человека к контакту или сборке проекта.

Ключевая идея страницы: спецпроекты Паблистеров - это не статичная презентация, а живая веб-упаковка с движением, ладошкой-проводником, интерактивными блоками и ощущением креативной лаборатории.

Контекст performance-фикса мобильной версии 2026-07-02:

- Главная причина тяжёлого первого открытия исследования на телефоне была в hero:
  декоративные Lottie-звёзды подключали крупный `lottie-react` runtime, а HTML preloaded
  desktop hero и изображения нижних секций. Для мобильного это давало лишнюю загрузку до
  первого экрана.
- В исходнике исследования `src/components/Hero.tsx` Lottie-звёзды заменены на inline SVG
  с тем же контуром и цветами; `lottie-react` не должен попадать в page chunk. Не возвращать
  Lottie в hero ради трёх декоративных звёзд без отдельной performance-проверки.
- Некритичные изображения ниже первого экрана помечены `loading="lazy"` и `fetchPriority="low"`.
  В актуальном экспорте `index.html` должен иметь только 2 preload в head: `header-logo.webp`
  и служебный script preload Next. Desktop hero image не должен быть preloaded на мобильном.
- Контейнерный nginx `docker/nginx/default.conf` включает gzip и cache headers:
  `_next/static/` кешируется на 1 год с `immutable`, остальные статические ассеты на 30 дней,
  HTML остаётся `no-cache`.
- После жалобы, что телефон продолжает не грузить страницу, выяснилось по access log:
  iPhone не запрашивал новый `index.html`, а использовал старый кешированный HTML и дергал
  старый heavy chunk `0d-rwp289d_1p.js`. Поэтому legacy page chunk-файлы
  `0d-rwp289d_1p.js`, `0jygeyb7dr5-n.js`, `0s-r44z9q6fzv.js`, `1_zb1yfmwc807.js`
  заменены содержимым нового облегчённого page chunk без Lottie. Для этих exact URL в
  контейнерном nginx задан `no-store/no-cache`, а HTML теперь отдаётся с
  `no-store, no-cache, must-revalidate, max-age=0`, чтобы мобильные браузеры не держали
  устаревший документ.
- Проверка после фикса на mobile viewport `390x844`, `deviceScaleFactor: 3`: hero чёрный,
  mobile image грузится из `image_main-640.webp`, `naturalWidth === 1280`,
  `scrollWidth === innerWidth`, failed requests нет.

Важные правила после инцидента с мобильной версией 2026-07-01:

- Не копировать экспорт командой `rsync --delete` в `research/telegram-channels/`.
  У Next static export имена CSS/JS чанков хешированные. Если удалить старые чанки, а у
  мобильного браузера останется старый HTML в кеше, страница может перестать открываться.
  Копировать новый `out/` нужно поверх существующей папки без удаления старых файлов:

  ```bash

    /Users/igorermolenko/Documents/Лендинг\ с\ исследованием/out/ \
    /Users/igorermolenko/Documents/Выгруза\ пптх/site-repo/research/telegram-channels/
  ```

- После копирования не тащить случайный binary churn: проверить `git status`, убрать
  неиспользуемые ассеты, если они не referenced в HTML/CSS/JS, и нормализовать права шрифтов
  (`chmod 644 research/telegram-channels/fonts/*.woff*`), чтобы не было mode changes.
- Мобильный hero не должен зависеть только от Tailwind 4 utilities внутри cascade layers:
  в исходном `src/app/globals.css` есть fallback-правила для `.hero-mobile` и `.hero-desktop`
  вне `@layer`. Их нельзя удалять без проверки в мобильном WebView.
- Для мобильной hero-картинки важно учитывать retina DPR. Файлы называются
  `image_main-640.webp` и `image_main-960.webp`, но фактически должны быть минимум

## Структура страницы

В hero есть бегущая строка с форматами: боты, mini apps, креативные розыгрыши, ai-механики, wow-посевы, перформансы, ugc.

### 2. Три стула / три пакета

Секция `#stools` объясняет три пакета работы:

- `S` - Чёткий запрос.
- `M` - Задача, решение и реализация.
- `L` - Проактивный креатив под ключ.

В этой секции встроена мини-игра как "непрогруженный кусочек страницы":

- до старта показан серый блок с текстом `Эта часть страницы не прогрузилась.`
- кнопка: `Кликни, чтобы починить`
- после клика запускается игра в духе Chrome Dino
- персонаж - фирменная ладошка в сером варианте
- управление: `Space` или клик/тап по игровому полю
- после проигрыша показывается сообщение: `Вот вам и вовлечение! Придумаем геймификацию и под вашу задачу)))`
- есть кнопка рестарта

### 3. Бриф-конструктор

Секция `#brief` собирает сценарий проекта из двух выборов:

- бизнес-задача
- режим работы / пакет

Данные лежат в `script.js`:

- `goalData`
- `packageModes`
- `briefVariants`

Важно: результаты должны заметно отличаться в зависимости от выбора. Если добавлять новые варианты, нужно менять не только заголовок, но и форматы, шаги, deliverables и общий режим работы.

## Сквозные интерактивы

### Ладошка-проводник

`palm-navigator` закреплён справа снизу и сопровождает пользователя по странице. Он показывает короткие подсказки в зависимости от текущей секции и прогресс по странице.

Если ладошка пропадает в проде, первым делом проверить:

- существует ли `assets/images/palm-guide.png`
- корректен ли путь в `index.html`
- не закешировались ли старые `styles.css` или `script.js`
- обновлён ли query-параметр CSS/JS в `index.html`

### Reveal-анимации

Основные секции используют класс `.reveal`. Появление управляется через `IntersectionObserver` в `script.js`.

### Hero parallax

В hero есть элементы с классом `.hero-parallax`, которые слегка реагируют на движение мыши.

### Интерактивные кнопки

Для `.chip`, `.case-card`, `.button` есть pointer-эффект через CSS variables `--x` и `--y`.

## Правила по текстам

Главное ограничение: на ключевых блоках использовать тексты пользователя и копирайтера, не переписывать их нейросетевым стилем.

Чего избегать:

- формулы `Не X, а Y`
- абстрактных фраз без фактуры
- слишком рекламных и общих формулировок
- выдумывания новых смыслов там, где уже есть утверждённый текст

Если текст нужно дописать временно, лучше делать его коротким, предметным и легко заменяемым.

## Правило перед коммитом

Когда пользователь просит закоммитить изменения, сначала проверить, не изменилось ли фактическое
состояние сайта, деплоя, структуры файлов или договорённостей по работе. Если изменилось - обновить
`MAIN_SITE_CONTEXT.md` в этом же коммите, чтобы контекст оставался актуальным для следующих задач.


страницу через fallback `try_files ... /index.html`.
